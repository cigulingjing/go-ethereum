## Context

项目使用 TinyGo 0.42 构建独立的 WASI 模块；Go 1.25 的 `crypto/sha256` 引入额外 FIPS/boring 依赖。旧制品为 68,288 字节，升级 Gas 为 863,044。`wasmtool.Build` 仅将单个算法源码和生成的 ABI wrapper 一同编译。

## Goals / Non-Goals

**Goals:** 保持 `Sha256([]byte) []byte` 与 SHA-256 语义不变；通过源码实现 SHA-256 压缩函数，缩小独立 WASM；用标准库作测试 oracle；留存可复现制品及 Gas 对照。

**Non-Goals:** 修改 Geth Gas 计价、CodeStorage ABI、其他算法或为生产环境提供未经审计的密码学库。

## Decisions

- 技术栈：Go 源码实现 FIPS 180-4 SHA-256，并沿用现有 TinyGo/WASI 和 `wasmtool`。只使用基本整数、移位和固定长度数组，避免 `crypto/sha256` 与其传递依赖；不引入第三方密码库。
- 在算法的独立 `.go` 文件实现完整 SHA-256，避免 `wasmtool` 单源码文件模式需要复制辅助文件。维持函数与 ABI 形状，从现有源码重新构建 WASM；不同模块哈希按正常升级版本处理，不覆写已上链历史。
- WASM 变小后，发现运行时固定在 64 KiB 写入 ABI 输入会覆盖某些模块的初始堆数据。模块初始化后从内存当前末尾分配固定输入区，保持原执行接口不变，并加入长输入的 WASM 回归测试。
- 测试按 FIPS 向量和确定性伪随机输入与标准库比较，覆盖 0、55/56、63/64/65 字节和多块输入；另外运行实际 WASM 执行入口验证 wrapper。记录优化前后尺寸和收据 Gas，便于论文报告。

## Risks / Trade-offs

- [手写密码学实现易出现边界或字节序错误] → 使用标准库对照及跨块、长输入回归测试；仅用于实验，不宣称独立实现安全审计完成。
- [旧 WASM 的哈希与优化后不同] → 保留历史实验结果；现有链上版本不原地替换，升级时使用新版本。
- [编译器或配置不同会改变制品尺寸] → 固定本次 TinyGo/Go 版本及构建命令，并记录新旧大小与 Gas。
- [模块执行期间继续增长内存] → 输入区基于实例初始化后内存末尾设置，保留原 256 页内存限制并用跨边界输入测试；避免在模块静态内存内写入。
