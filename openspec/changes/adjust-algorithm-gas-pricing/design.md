## Context

技术栈：Go、ethereum/go-ethereum、OpenSpec；复现实验位于 `experiments/cryptoupgrade`。现有 `cryptoupgrade/internal/evm/code_storage.go` 仅对 `callFunc` 读取算法 Gas；`cryptoupgrade/plugin.go` 按已激活版本返回固定费用；`core/vm/contracts_cryptoupgrade.go` 在执行前扣费，目前仅传入区块高度，没有父区块调用量或交易内算法计数。参见 `proposal.md` 和 `specs/cryptoupgrade-algorithm-gas-pricing/spec.md`。

## Goals / Non-Goals

**Goals:** 以小范围 EVM 集成实现共识确定的区块基准和交易内指数定价；标定数据可审计、实验可重复；历史调用保持原价。

**Non-Goals:** 不改变 EIP-1559、原生 precompile 的计价或现有 CodeStorage ABI；不把本地监控统计用作共识输入。

## Decisions

1. **定义可执行的公式。** 把用户公式中的方括号解释为 `ceil`。`i` 为同笔交易中规范化算法名的第几次成功扣费调用（不同版本仍沿用同一交易中的该算法计数）；`g_0(a_i,x_i)` 根据该调用已激活的算法版本和 ABI 解码后的输入确定。标定结果以固定的算法/版本、输入长度或规模分段映射及单位 Gas 常数写入激活配置，覆盖所有可调用算法；拒绝缺失/非法的标定配置而不是依赖节点本地测量。`α`、`m_k` 以非负有理数表达，使用整数有理数运算、一次性向上取整，禁止浮点。选择有理数而非浮点是为了跨节点重放一致。

2. **确定 `m_k` 的来源。** 在链共识配置中固定单调不减的有界查表函数 `M(C)`，包含 `M(0)=1`；`C_{k-1}` 是父区块中已成功扣费的 `callFunc` 次数，包含最终交易失败及内部回滚前已发生的调用，排除未纳入区块的模拟调用。首个激活区块约定 `m_k=1`，以后逐区块从**对应父区块哈希**获取计数。缓存按区块哈希索引、重组后重新选取对应分支；重启/历史重放必须能从父区块交易执行结果重建计数，不能依赖易失内存或 receipt log。对比按本机实时请求量定价：后者会破坏共识。

3. **隔离调用状态。** `cryptoupgrade` 中放纯计价器与 profile 校验；`core/vm` 只传父区块基准、当前交易计数和输入给计价器，并在实际扣费成功后计数。交易开始清零、内部调用共享计数，EVM state snapshot 回滚不回滚已耗 Gas 的计数；区块上下文持有父区块基准及本区块临时统计，只有被纳入区块的交易纳入父区块计数，估算、`eth_call`、trace 和构块试算使用独立上下文。把计数放入全局 `cryptoupgrade` 单例会混淆并发调用，因此不采用。

4. **控制计算成本。** `α`、`M` 和标定表随链配置及激活高度固定，参数由实验选定后写入配置；pow 使用有界整数运算或提前比较 Gas 上限，在费用超过 `uint64` 或 Gas 预算时返回现有 out-of-gas 语义，不允许截断或饱和后成功执行。不能为防溢出而降低指数或隐式封顶价格。旧区块走旧规则；生产网络默认不启用。启用节点需相同的配置及明确的激活高度，避免热修改共识参数。

5. **可复现标定。** 在 `experiments/cryptoupgrade` 增加分算法/版本/输入规模的重复测量与 profile 导出、参数记录、基线对照。区分校准采集的墙钟时间与链上 `g_0`，只有经审阅的静态 profile 可进入共识配置；测试阈值、跨交易/区块、失败回滚、重组、估算和重启重放。八算法首次标定及实验候选基础费见 `experiments/cryptoupgrade/results/gas-complexity/README.md`；这些样本不覆盖全部输入与升级版本，不等于已经确认的共识 profile。

## Risks / Trade-offs

- [父区块调用量没有现成持久字段] → 按父区块哈希缓存并提供可重建来源；在实施前先验证各执行路径的重放可行性，不得用本机实时统计替代。
- [重放计数可能引入昂贵的递归父区块重执行] → 设计缓存和可校验的派生持久索引；缺失时从既有规范执行流程重建，避免在热路径反复全链回放。
- [指数费用或恶意输入导致 DoS] → 输入规模有界、参数及函数表有上限、计算提前按剩余 Gas 截断为 OOG 而非循环乘法。
- [未标定算法/动态升级版本] → 激活前校验覆盖范围；新增版本须提供确定的标定数据和生效规则，不能由单节点热改价格。
- [`eth_estimateGas`、内部回滚或并发构块与导入不一致] → 共享纯计价规则、隔离模拟上下文，并用相同区块序列做一致性测试。

## Migration Plan

1. 完成旧固定费用与标定 profile 的对照实验，确定 `M`、`α`、`N_0` 及激活高度；未确认参数之前不开启新规则。
2. 在单独实验链配置中激活并让所有参与节点使用相同配置；既有区块不重写。跨节点对比交易 receipt、区块 Gas used、重组及重启后的重放结果。
3. 回退时停止在该高度之后继续构块，使用未激活的实验链或在后续预定升级高度切换规则；不得单节点静默切回旧费率。
