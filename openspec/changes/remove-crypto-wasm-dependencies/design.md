## Context

当前 `wasmtool.Build` 仅编译单个算法文件与生成的 wrapper；Ed25519 的三 `bytes` 参数接口尚无 wrapper。SHA-256 已有实验性纯 Go 实现，可作为算法内联计算基础。

## Goals / Non-Goals

保证测试对照下的算法结果和现有调用 ABI；不修改预编译合约或 GAS 公式，不将实验源码当成经审计的生产库。

## Decisions

- 每种独立 WASM 算法文件内包含必要计算逻辑；避免改变现有单源码构建契约，SHA-256 复用相同实现但需在独立文件中包含。相比新增通用模块打包机制，这一选择仅修改实验算法及必要 ABI wrapper。
- PBKDF2 用按块 SHA-256 实现 HMAC 的内外 pad 与迭代异或；保留输入限制。Ed25519 用 FIPS SHA-512、RFC 8032 点解码/标量乘与群方程，测试与 Go 标准库及 RFC 向量对照。
- WASM 制品仅重新构建已发布的两种算法；Ed25519 如原本未提供制品，则新增制品前必须通过相同 ABI 的端到端验证。

## Risks / Trade-offs

- [手写 SHA 与曲线运算易引入错误或计时侧信道] → 仅用于实验，对照标准库的正反例、边界与畸形输入；不得作为生产安全组件。
- [Ed25519 使用大整数运算可能耗时较高] → 在实际 WASM 调用上测试资源和超时，不因删依赖宣称 Gas 必然降低。
- [重新编译改变模块哈希] → 历史链上版本保持不动，新制品用于后续升级实验。
