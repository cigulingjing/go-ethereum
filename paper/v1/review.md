# 修改意见

P0级别的问题
1. Acutivation Block机制本身并没有真正解决共识分叉问题。节点更新失败如何解决？
2. Immediate activation 的语义存在明显疑问，4.4节的immediate模式不合法，需要删除
3. 动态加载 Native Go plugin 带来了比升级机制本身更大的安全边界？
4. 同一源码各节点本地编译不能天然保证确定性

p1级别的问题
1. 创新点与 Phoenix / Polkadot / Precompile 的差异还不够锋利
2. 论文标题和动机强调 cryptography，但实验没有真正验证密码迁移场景
3. Lab3 目前更像功能测试，而不是 State Consistency 实验
4. 实验私有链规模需要扩大

# 针对修改

p0对应的问题
1. 升级协议的稳定性需要继续优化协议，对于在线的客户端通过监听事件可以完成升级任务，对于离线的客户端可以通过查询合约索引，获取到当前最新的算法版本值。与本地密码库进行对照，如果已经陈旧，则需要从合约侧读取对应的tx hash，查询获取到当时的事件信息。
2. Immediate activation 本身是不合法的，发布升级交易后，异步完成升级，需要等到提案中指定的activation Block才能完成涩会给你及
3. 安全问题，我们安全假设是治理区确保代码的合法性，当客户端在处理交易的时候考虑一些安全攻击的防御机制
4. 源码编译不一致问题，依然是使用源码的思路。
